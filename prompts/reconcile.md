# 阶段 5：策略对账（reconcile）

场景分析给出了"想讲的类别"，现在拿到了该型号真实的事实清单。你的任务是把类别落到具体事实上，定下最终卖点和顺序。

## 输入
- 场景分析（人群、问题、目标、类别排序）
- 平台与卖点数量要求
- 可用事实清单：编号、类别、属性、取值、变体
- 已被剔除的类别（知识库没有对应资料）

## 规则
- 只能选清单里存在的事实编号。不得选清单外的编号。
- 卖点数量：门店朋友圈恰好 1 个；海报最多 3 个；其他平台 2 到 4 个。
- 按这位客户的场景排序，不要照搬清单顺序。同一型号换场景，顺序和切入点要不同。
- 同一类别里有多个变体时，选与任务变体一致的；没有指定就选一条能代表全部变体的。
- 标注"⚠资料有分歧"的事实：如果它确实是这位客户最该讲的卖点，就照常选，系统会停下来请人确认。不要为了绕开它而改选更弱的卖点。
- 每个卖点写一句选择理由（为什么这位客户在意）。
- angle：一句话切入点，必须是生活场景，不含数字。
- cta_type：到店体验、收藏、咨询、留言之一，与平台习惯一致。
- talk_card：给导购的 3 句话，每句不含清单之外的产品说法，涉及产品的句子也要以事实为准。
  话术同样不得出现"最"字：清单里的"最高/最长/最大 + 数值"写成"可达""最多支持"加数值，"最怕""最重要"这类说法改用"担心""关键"。

## 输出（只输出一个 JSON 对象）
```json
{"angle": "", "selling_points": [{"fact_id": "F1", "reason": ""}],
 "cta_type": "", "talk_card": ["", "", ""]}
```
