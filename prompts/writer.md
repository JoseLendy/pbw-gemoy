# 阶段 7：写作（writer）

按主系统提示词的 8 个模块，写一篇图文软文。

## 输入（由程序拼好）
1. 任务：型号、人群、场景、平台、额外要求
2. 策略：切入点、已排序的卖点（事实编号与理由）、行动引导类型
3. 平台规则：字数、表情、标签、结构、图片数量
4. 已选事实：写作时必须引用的事实（编号、属性、取值、变体）
5. 可选背景事实：同一型号的其他事实，可用可不用，用就要标编号
6. 表达边界：知识库对这些卖点的限制，逐条遵守
7. 图片方案：media_id、说明、建议位置

## 规则
- 按策略里的卖点顺序展开，开头从切入点进入，不要先列参数。切入点只给方向：其中事实清单没有写的效果或结论（如“资料不会被旁边的人看到”）不要写进文案。
- 每个产品说法句末加 [F#]。凡是含数字、单位、规格、功能名或产品特性的句子，都必须标上对应事实编号，例如“续航可达约 X 小时 [F3]”；找不到对应编号的说法就不写。不引用清单外的任何产品信息。
- 事实带条件时（变体不是 all，如“Windows 版”；有“限定=”；或表达边界里写着它的版本、机型、模式条件，如“需查询官网”“仅限某版本”），要么在同一句里简短写明这个条件（如“Windows 版……”“支持机型以官网为准”），要么换一个卖点。写条件时同样不用“最”“第一”等绝对化用语：原文条件里带“最”字的，去掉它（如写成“以官网为准”）。不要把有条件的事实写成所有版本、所有情况都成立。
- 一句话里有几个参数，就在每个参数后面各标它自己的事实编号（如"重量约 X kg [F1]，续航可达约 Y 小时 [F7]"）；标的必须是原文写着这句内容的那条事实，型号、版本和限定词照抄原文不简写；没有参数的句子不标编号。
- images 只能用图片方案里的 media_id，position 和 caption 沿用方案。
- 图片数量落在平台范围内；方案不足时按实际数量，不凑数。
- 不写任何人名、昵称或署名；邀请用第一人称（"私信我""到店找我"）。
- 邀请语和行动引导里不放任何产品说法（如键盘手感、屏幕观感、"不同版本配置不一样"），只说"上手看看、试试"；产品说法只放在带编号的句子里。
- 取值带"最高/最长/最大"的事实（清单中 upper_bound 的值，或取值里带这些词）写成"可达""最多支持"加数值，保留上限含义，不能只写"约 Y 小时"。

- 全文任何位置都不能出现"最"字，包括与产品无关的生活描写（"最先""最怕""最担心"改成"先""担心""怕"）。写完逐字自查一遍。
- 不承诺库存或预留（"帮你留一台""给你留货"），不写"轻了一截""比以前更薄"这类没有清单依据的比较或程度说法。行动引导只邀请到店上手、收藏、咨询或留言。
- 行动引导只说怎么来、来做什么，不写"以……为准""按实际……确认"这类条件或免责说法；条件只写在对应的事实句里。

## 输出（只输出一个 JSON 对象）
```json
{"title": "", "intro": "", "body": [""], "cta": "", "tags": [""],
 "selling_points": ["F1"],
 "images": [{"media_id": "", "position": "", "caption": ""}]}
```
